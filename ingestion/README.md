# Ingestion

Format-agnostic readers and deterministic validators for organizer race and result files (CSV or XLSX), matching the published contracts in [`data/schemas/`](../data/schemas).

- `reader.py` — reads a CSV, TSV or XLSX file into a header and rows of stripped strings: it works out the separator (comma, semicolon, tab, pipe) and the encoding (UTF-8, UTF-16, Windows-1252), skips title lines above the header, and turns spreadsheet date, time and duration cells into text.
- `normalize.py` — from an organizer's export to OTRI's result fields: matches the headers, splits a single name column, reads gender out of a category, turns `FR` / `France` / `GER` into ISO alpha-3 (`countries.py`, generated by `scripts/generate_country_table.py`), rewrites `12h34m56s` and the like as `H:MM:SS`, counts a row with no time and no position as DNF, and works positions out from the times when the file has no overall ranking. It records the header each field came from (`ResultTable.columns`) and warns about everything it did that a reader of the file might not expect.
- `schema.py` — canonical field names, organizer header aliases, required/optional flags, and per-field validation rules. Mirrors `data/schemas/race.schema.json` and `data/schemas/result.schema.json`.
- `validate.py` — `validate_race_file()` and `validate_result_file()`, returning a deterministic `ValidationReport` (errors block ingestion, warnings do not).

One intentional gap between the two layers: the published JSON Schema treats `gender` as a strict `M`/`F`/`X` enum, while the Python validator accepts other values as a **warning**, since real organizer exports are not always pre-cleaned.

For a results file only a finish time and a name are required. `rank` accepts a position or the non-finisher codes `DNF`, `DNS`, `DSQ` (and their usual spellings: "Did not finish", "Abandon", "DQ" …); a `status` column, or the time cell itself, may carry the code instead. Errors are limited to what a score cannot be made without: a finisher with no readable time, a runner with no name, no time or name column, several race distances in one file. Oddities in the ranking or the bibs are warnings, and a message repeated on many rows is listed fifteen times and then counted. The shapes of export this is tested against (ITRA / UTMB sheet, RaceResult, LiveTrail, a Thai spreadsheet, a bare finisher list) are in `tests/unit/test_ingestion_exports.py`; new header names go in the alias lists in `schema.py`.

## Usage

```python
from ingestion import validate_race_file, validate_result_file

report = validate_result_file("data/demo/results/OTRI-DEMO-001.csv")
print(report.is_valid, report.errors, report.warnings)
```

Run `pytest tests/unit` from the repository root to exercise these against the demo dataset in [`data/demo/`](../data/demo).
